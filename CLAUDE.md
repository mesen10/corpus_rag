# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Local RAG (Retrieval-Augmented Generation) demo. No cloud APIs: Ollama for embeddings + LLM, Qdrant (local on-disk mode, not a server) for vector storage. Pipeline: PDFs/text in `books/` → chunk + embed → Qdrant → query with RAG vs No-RAG and score via LLM-as-judge.

Deliberately uses small local models (2B-3B) so answers can only come from retrieval, not model memory — proves RAG is doing the work. See `readme.md` for full rationale and model recommendations.

## Setup / commands

Requires Ollama running locally with two models pulled:
```bash
ollama pull nomic-embed-text   # embedding model
ollama pull llama3.2:3b        # generator model (compare.py uses tag "llama3.2")
```

Python deps: `pip install -r requirements.txt` (langchain + langchain-ollama + langchain-qdrant + qdrant-client + pypdf).

Pipeline, in order:
```bash
# 1. Put source PDFs/txt/md/json files in ./books/ manually (download_books.py's
#    Gutenberg fetch path is deprecated per readme.md — books/ now holds policy PDFs instead)
python ingest.py     # chunks + embeds books/ into ./qdrant_storage (destroys and rebuilds the collection each run)
python compare.py    # runs the 20-question benchmark: No-RAG vs RAG, scored by an LLM judge
```

There is no test suite, linter, or build step — this is a two-script demo pipeline. "Running it" means executing `ingest.py` then `compare.py` end to end against Ollama.

## Architecture

- **`ingest.py`**: loads every `.txt/.pdf/.md/.markdown/.json` under `books/` (PDFs loaded page-by-page via `pypdf`), splits with `RecursiveCharacterTextSplitter` (`CHUNK_SIZE=400`, `CHUNK_OVERLAP=120` — intentionally small/overlapping to preserve exact policy figures like dollar thresholds and day counts), embeds with `nomic-embed-text` via `OllamaEmbeddings`, and writes into a Qdrant collection (`corpus_docs`) at `./qdrant_storage`. Auto-pulls the embedding model via the `ollama` Python client if missing. Always drops and recreates the collection — not incremental.
- **`compare.py`**: hardcodes a 20-question eval set (`TEST_DATASET`, question + expected-answer pairs) against the currently ingested corpus. For each question it gets a No-RAG answer (bare LLM), a RAG answer (via `build_rag_chain`, MMR retrieval `k=6, fetch_k=15, lambda_mult=0.65`, `format_docs` labels chunks as `--- CONTEXT CHUNK N ---`), then uses the same LLM as a judge (`evaluate_answers`) to score both 0-5 against the expected answer and prints a scoreboard. `TEST_DATASET` is coupled to whatever documents are currently in `books/`/`qdrant_storage` — changing the corpus without updating the questions will make the benchmark meaningless.
- **`download_books.py`**: fetches public-domain Gutenberg texts (Odyssey, Alice in Wonderland, Romeo and Juliet, Crime and Punishment) and strips Gutenberg header/footer boilerplate. Superseded — readme.md notes those books are too well-known/memorized by LLMs to prove retrieval is doing the work, so `books/` is now populated manually with lesser-known policy/handbook PDFs instead (see readme.md "Included Document" for the current sourcing method).
- **`qdrant_storage/`**: on-disk Qdrant database (SQLite-backed), regenerated by `ingest.py`. Delete it to force a clean rebuild.
- **`sample-results.md`** / readme's embedded sample output: reference benchmark run showing RAG (80%) dramatically outscoring No-RAG (32%) on the policy-handbook question set — useful for sanity-checking that a change hasn't regressed retrieval quality.

## Editing notes

- Model names, chunk size/overlap, and retriever search params are all top-of-file constants in `ingest.py`/`compare.py` — change them there, not inline.
- If you change `CHUNK_SIZE`/`CHUNK_OVERLAP`/embedding model in `ingest.py`, re-run `ingest.py` before `compare.py` — the vector store doesn't know its own config drifted.
- If you add/remove documents in `books/`, re-run `ingest.py`; if the new corpus no longer contains the facts `TEST_DATASET` asks about, update `TEST_DATASET` in `compare.py` accordingly.
